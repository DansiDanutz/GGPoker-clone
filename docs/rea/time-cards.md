## Local owner policy and implementation

Admin can configure0–100 free cards per seating,1–300 seconds per card and1–10 cards per action. Zero disables cards. Cards and the continuous GameClock pool are mutually exclusive. These are explicit local controls/bounds,not claims about operator defaults. Occupied-table settings cannot change. Create/Edit/Duplicate preserve the settings; card duration/limit inputs are disabled while cards are off. A server capability header hides this configuration on an older running backend,preventing a misleading save that silently drops unknown fields.

The local manual policy adds the configured duration to the current deadline. A card may be used in the final5seconds of the base action; after the first card,the remaining allowed cards can be used during its extended time. This corresponds to the native visible phase gates,but the exact native server deadline arithmetic is not proven. Inventory is granted once per seating and has no automatic refill. Paid actions and the separate manual per-turn toggle request remain rejected; automatic policies described below use persisted preference flags; no wallet or wager is charged. The four automatic-preference options are now connected through the settings page described below.

The existing time-bank operation binds actor and action ID. Manual cards additionally require the current per-action sequence; retrying an accepted sequence is idempotent and cannot decrement or extend twice. Future/fractional/stale/foreign requests,reached per-turn limits and exhausted inventories are rejected. Inventory and action counters persist with the room. Invalid actions or failed writes retain prior state; save rollback includes consumed count,sequence and deadline. Cards do not reset on action/hand changes or reload/restart. Taking a new seat starts a new local seating grant.

Only the seated player receives their inventory field; spectators receive none. The private completed-hand journal records accepted time-card-used events (seat,street,action boundary,sequence,duration),without copying remaining inventories into other players’ reports. Existing clock-limit-disabled events remain separate.

The button operates on actual room state,displays the count and respects the cap/disabled source artwork. The Time Bank hotkey invokes the same enabled control,with existing Functions/global/typing guards. Stats displays TimeBankCard plus the numeric inventory,not a fabricated continuous pool. Native NTime caption translation is fitted to the button width. Paid price tags,reservation ticks and paid animations are not fabricated.

## Automatic policies and settings

Additional bounded source exports establish both SetTimeBankOptionCommand paths. The app command broadcasts SET_TIME_BANK_OPTION to tables; the table command sends auto-action flags from PlayInfo.getTimeBankOption. TimeBankSetting constants map0=Always,1=including blinds/ante,2=voluntary money,3=Never to TimeBankAlways/PutMoney/VoluntaryPutMoney/None. UserSetting’s compiled default is2; the actual saved native user choice was not observed. The local implementation deliberately preserves PR81’s manual3 until a choice is explicitly saved,avoiding automatic consumption for existing local seats. This default difference is documented rather than presented as recovered native behavior. Invalid local preferences fail closed to manual.

The settings page uses the native four choices,keys,explanations and source toggle graphics. Title(33,20),choices(36,63),width748,heights78/78/78/60,pitch90,14px labels/explanations and footer(57,404) follow OptionTimeBankChipPage. Text comes from the current private native catalog; radio identities do not depend on translations. Inputs separately reference their caption and explanation for accessibility. Selection is draft-only; OK commits,Cancel/Escape discard. Other-window storage updates preserve a dirty draft through the existing settings lifecycle. The page is unavailable on backends without the automatic-policy capability header.

The saved browser preference is sent to each open supported table using its own seat token. The strict private endpoint accepts only an integer0..3 and cannot target another seat. The selected rule persists in the room independently of browser lifetime. Reopening a table synchronizes an explicitly stored browser choice; closing the table does not erase the server’s last accepted choice. Changing a preference while no table client is open reaches that seat when it reconnects,matching the local open-table synchronization scope.

At expiry,the shared room transition consumes an eligible free card before folding/checking. Always is eligible on every active turn;including forced chips requires a positive hand contribution;voluntary mode requires an actual positive call/bet/raise contribution. Tracking covers all streets,not just preflop VPIP,and is reset per hand. Blinds/antes never mark a voluntary contribution. Known preflop VPIP also establishes voluntary eligibility for legacy hands. Historical postflop-only contributions without markers remain conservative until a later paid action/new hand. Never disables automatic use while preserving the manual button.

Automatic use shares the same finite inventory/per-action limit as manual use. Repeated ticks cannot consume the same boundary twice. A delayed/offline server catches up only within remaining inventory and the configured per-action cap;it then resolves an expired action if no time remains. Both periodic tick and request-time expiry call the same transition. Each accepted automatic use creates one journal event with automatic:true and its sequence;failed saves roll back the count,deadline,event and version. No wager/wallet values change. The precise native server scheduling/deadline arithmetic remains unobserved;this is the explicit local policy.

An eligible armed button uses native table415 reservation art (35×36 crop,52.5×54 display at84/−10),in addition to the existing free/counter textures. Its armed state is the local rule’s eligibility,not a claim to have observed native runtime Reserved notifications. Paid/refill/usage motion and physical tooltip/font/sound timing remain separate work.
