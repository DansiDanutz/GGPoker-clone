# Local Group entry funding — candidate, not live

REA: [native Group join contract](cash-group-join-source.json) now includes the original CheckTakeSeatCommand. After CashGameReady, the selected nonzero TempAutoJoinVo.buyInAmount and isAutoBuyIn reach BalanceSetting/TAKE_SEAT. Play-money values are not currency-exchanged. Native private matching thresholds and batch atomicity are not established by this client trace.

The local backend reuses the existing bankTransaction snapshot/atomic file rename and ordinary authenticated room join. One request buys1–6 distinct hosted Hold’em cash seats for the selected whole-chip amount. Only identical existing normalized room rules are grouped; selected table comes first, then stable table IDs. These are explicit local policies, not a claim about the native server’s private algorithm. Other game modes, advanced matching preferences, tickets and currency routing are not silently approximated: they remain outside this candidate API.

POST /local/cash-group-join requires the current local cookie/account, exact local Origin and JSON up to1024bytes. Fields: account, operation(48lowercasehex), tableId, count(1–6), buyIn. It rejects wrong methods, expired/wrong-account sessions, unknown fields, invalid counts/amounts, closed groups, insufficient balance or insufficient matching capacity. Reserved seats and FIFO offers retain their existing priority. Any joining or persistence failure rolls back every room and the wallet.

The bounded1000-entry receipt ledger is stored in the existing cash wallet checkpoint. Its account/operation/command/seats and player links are validated on restart. No new logical root or raw session token is persisted. Initial private/no-store response returns real issued seat tokens; replay returns the same seat receipts without new tokens or debit. A changed command is409; a receipt with departed seats is410 and cannot purchase again. Existing authenticated profile recovery can rotate the actual seat token without funding again; its reservation route returns seated:true for an already seated account.

Validation: missing-method RED then unit/HTTP GREEN real1/3/6-seat entries, total debit, replay/restart, disk failure rollback, closed receipt, closed/changed-rules groups, insufficient funds/capacity, actual FIFO offer/private cards and logout. Previous installed runtime read/write/token recovery preserved the new optional wallet ledger and upgraded replay; invalid checkpoint rejected. Existing waiting/wallet-room/add-chips/HUD HTTP regressions passed. One initial regression invocation used nonexistent cash-wallet-test.mjs; corrected to actual wallet-room-test.mjs, no assertion dropped.

No lobby dialog is connected yet and this candidate is not deployed.
